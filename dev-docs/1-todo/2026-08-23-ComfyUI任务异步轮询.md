# ComfyUI 任务异步轮询

> 状态：待实现
> 记录日期：2026-08-23
> 对照日期：2026-08-27
> 关联实现：`dev-docs/2-in-progress/20260823-ComfyUI工作流支持/`

## 背景与现状

当前图片、视频生成及工作流真实试运行在提交 ComfyUI 任务后，会在请求或消费线程中循环查询状态并调用 `Thread.sleep`。对照主干，阻塞点在：

- `ComfyUiGenerationExecutor.waitForJob()`：`while` + `Thread.sleep` 查询 `/api/jobs/{id}`
- `ComfyUiImageStrategy` / `ComfyUiVideoStrategy`：生成时调用 `waitForJob`
- `ComfyUiWorkflowValidationService`：真实试运行同样等待 job 结束
- `ImageGenerationConsumer.submitAndWait` / `VideoGenerationConsumer`：Agent 同步等待本地任务终态时也在 `Thread.sleep`

项目已有任务表、远端任务 ID 和 Redis 定时消费能力，但生成任务领域还没有可复用的“状态落库 + 调度器单次轮询”。`ImageGenerationService.findPendingTasks()` / `VideoGenerationService.findPendingTasks()` 目前没有调度调用方。

AgentScope 模块已有数据库租约、批量领取、超时重试与重启恢复，可借鉴调度思想，但不直接复用其业务实体。

## 目标方案

新增通用远端轮询任务表，至少记录：业务任务类型与 ID、ComfyUI `promptId`、状态、`next_poll_time`、`deadline_at`、领取者、租约截止时间、尝试次数和最后错误。

调度器按到期时间批量领取任务，每次调度只向 ComfyUI 查询一次：

- `pending` / `in_progress`：计算下次轮询时间，更新记录并释放当前线程。
- `completed`：按输出绑定下载、存储结果，再将本地业务任务置为成功。
- `failed` / `cancelled` / 超时：写入明确终态和错误信息。
- 进程重启后继续处理未完成记录；多实例通过条件领取和租约避免重复轮询。

正式图片/视频生成与工作流真实试运行都要接入该机制。模型或实例并发额度必须持有到远端任务进入终态，不能在提交成功后提前释放。

## 实施待办

1. 设计轮询任务表、状态机、索引、租约与超时恢复规则，并新增符合当前产品版本的 Flyway 迁移。当前对外产品版本是 `1.0.0`，新增迁移前先核对 `db/migration/` 与 `flyway_schema_history`，避免和已有 `V1.1.1.0.0`、`V1.1.2.0.*`、未提交的 `V1.1.3.0.*` 冲突。
2. 将 `ComfyUiGenerationExecutor` 拆成“提交任务”和“单次查询/结果收敛”，移除 `waitForJob` 的阻塞等待。
3. 实现支持多实例安全领取的定时调度器，以及失败重试、超时、取消和重启恢复。
4. 改造图片生成、视频生成和工作流真实试运行调用链，并处理业务任务终态与并发额度的一致性。
5. 增加状态机、租约竞争、重启恢复、取消竞态、超时和结果持久化测试。

## 验收标准

- ComfyUI 正式生成和真实试运行链路不再使用 `Thread.sleep`，也不长期占用 HTTP 或队列消费线程。
- 服务重启后未完成任务可继续轮询；多实例下同一轮询任务不会被并发重复处理。
- 成功、失败、取消和超时均能稳定收敛到本地终态，结果与错误信息可追踪。
- 远端任务完成前不会错误释放并发额度。
