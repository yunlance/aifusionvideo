# Flyway 迁移命名约定

## 文件名

版本化迁移统一使用：

```text
V<产品主版本>.<产品次版本>.<产品修订版本>.<迁移序号>__<英文描述>.sql
```

- 版本从 `1.0.0` 起。
- `<产品主版本>.<产品次版本>.<产品修订版本>` 必须与迁移所属的产品版本一致。
- 同一产品版本内的迁移序号从 `0` 开始连续递增。
- 描述使用小写 snake_case。

例如，产品版本 `1.0.1` 的前两条迁移为：

```text
V1.0.1.0__first_change.sql
V1.0.1.1__second_change.sql
```

## 基线迁移

基线用于让全新空数据库一次性完成建表并写入初始化数据。文件名使用：

```text
B<产品主版本>.<产品次版本>.<产品修订版本>__baseline_<产品版本>.sql
```

- 文件名中的版本必须与 `__baseline_` 后的产品版本完全一致。
- 基线必须从执行完该版本全部 V 迁移的全新数据库导出最终结构和必要初始化数据。
- 导出时必须排除 `flyway_schema_history`、数据库名、`CREATE DATABASE` 和 `USE`。
- 全新空数据库会先执行基线，再执行版本高于该基线的 V 迁移。
- 因此版本化迁移的版本必须高于基线版本，否则全新库执行基线后不会再执行它。

当前仓库只保留一条基线 `B1.0.0__baseline_1.0.0.sql`，即产品 `1.0.0` 的完整快照。
全新部署时 Flyway 只执行这一条迁移即可完成建表与初始化数据（含影视演示项目）；
管理员账号由后端 `DataInitializer` 在首次启动时创建，`sys_user` 自增从 1 开始，
与演示项目归属的 `user_id = 1` 对应。

本项目此前未对外发布，历史 V 增量迁移已整体移除，不存在需要增量升级的在库历史。
已有旧库需要升级时，请按全新部署处理或单独编写数据迁移脚本。

## 已执行迁移

基线是全新部署的唯一入口，一旦发布即不可修改。此后的结构变更必须新增版本高于基线的
V 迁移，不能回改基线文件。

已在持久化数据库执行过的迁移是不可变历史，不得修改内容、版本或文件名。仅在可丢弃的
本地开发库执行过、且确需改名时，优先重建本地数据库；必须保留数据时，需在确认 SQL
内容与 checksum 未变化后同步修改本地 `flyway_schema_history` 的 `version` 与 `script`，
随后执行 Flyway validate。禁止在共享、测试或生产数据库中用这种方式改写历史。

## 校验

新增或调整迁移后，至少在 `yunlan-video-server/` 目录运行：

```bash
./mvnw -Dtest=FlywayMigrationNamingTests test
```

并通过应用启动或等价方式完成 Flyway validate。
